# RAM findings: applied fixes and measurement boundaries

The findings in [RAM_GROWTH_FINDINGS_2026-10-13.md](RAM_GROWTH_FINDINGS_2026-10-13.md)
were read in full. Its live measurements are historical evidence from that investigation;
the fixes below do not establish the cause or magnitude of the September system-wide drift.

## Runtime retention

- Dispatcher runtime sessions have a default **256-session LRU cap** and **24-hour idle expiry**.
  `ISHTI_SESSION_CACHE_MAX` (1–4096) and `ISHTI_SESSION_CACHE_TTL_S` (1–604800) configure the limits.
  Every request leases its shared session, including waiting follow-ups and early returns. Active
  leases/running requests are protected; release trims excess idle state. Peak entries may exceed
  the cap while all entries are active. Associated INFLIGHT conditions leave with evicted sessions.
  Durable chats are not deleted; later access restores their bounded persisted history. Transient
  pending questions in evicted idle sessions must be asked again.
- Vault approvals expire after 120 seconds and are swept on prepare/consume. At most 256 live
  approvals remain. Oldest overflow approvals are invalidated; expiry/target binding/one-use
  confirmation still apply. A lock makes competing consumes atomic.
- The current WebSocket code already removed disconnected sockets in `finally`. The additional
  fix cancels **and awaits both** receive/event tasks on disconnect or handler cancellation and
  unsubscribes the event callback, preventing a pending queue task from retaining a closed handler.
- The task-result bound and closure release already exist. Their old comments claimed an
  unsupported multi-GB magnitude from 12 × 200 KB; that claim was corrected without removing bounds.

## Finite and distinguishable soak runs

`tools/load_ramp.py` now supervises a disposable subprocess; the supervisor does not import the
dispatcher or carry its executor. All writable application stores in that worker use test/scratch
mode. Each run gets a timestamp/UUID tag, unique summary/metrics/turn/log/config paths and scratch
directory. Existing level-only summaries and historical samples are preserved. Analyser rows pair
each summary with **its own tag**, and generated CSV files are unique, never overwriting old tables.

Turns stream to JSONL. Only aggregate counters, three error examples and the first token timestamp
are retained, rather than all turn records and every token. Metrics flush after each sample. Every
join shares one cleanup deadline. The supervisor waits at most startup allowance + measurement
window + cleanup grace, then cleans only its child tree. Forced cleanup, partial startup, unfinished
calls and errors are explicit and produce a nonzero exit; they cannot become a successful soak.
Run-owned artifact directories can be archived later; this change does not delete past evidence.

Profiles distinguish the paths under measurement:

- `skills` (default): the original dispatcher workload, largely rule-fast skills.
- `inference`: direct `llm.chat(..., role='planner')` calls on timeless prompts, without tools.
- `mixed`: alternating dispatcher and direct planner calls. This is not a desktop or HTTP app soak.

These profiles honour the owner's configured provider/model; there is no silent provider switch.
The inference profiles can invoke that provider when explicitly run. The offline regression tests
use fakes; their pass does not measure actual inference latency or model memory.

Example, from the checkout:

```powershell
venv\Scripts\python tools\ram_attrib.py 4 480 ramcheck --profile mixed
venv\Scripts\python tools\analyze_metrics.py --metrics-dir metrics
venv\Scripts\python tools\qa\ram_gate.py metrics\ram_attrib_<generated-tag>.jsonl --pid <app-pid>
```

`ram_attrib.py` runs its sampler separately from the workload. Expensive Python allocation tracing
is disabled by default. `--trace-python` traces only the sampler supervisor (six frames), clearly
labelled; use `ISHTI_MEMORY_PROFILE=1` on the actual app for allocation attribution inside the app.
Process samples record PID **and creation time**, RSS/private bytes and app/model/harness/other
roles without saving command lines. A reused PID cannot combine separate lifetimes into one slope.
The monitor now includes **available RAM** as well as system used RAM.

## Enforced attributed gate

`tools/qa/ram_gate.py` reports PASS / FAIL / UNMEASURED and exits 0 / 1 / 2 respectively.
By default it evaluates recognized app processes; `--pid` selects exact target processes explicitly.
It requires creation-time identity and a minimum **120-second** measured span **after 60-second
warmup**. More than **20 MB/min RSS growth** fails. Missing/exited targets, PID changes without
sufficient windows, and short/empty records cannot pass. Sampling gaps over five seconds also
make the gate unmeasured. The thresholds can be set explicitly for a controlled workload.

System first/last-quarter drift above 500 MB is context/warning, not an app-leak failure on a shared
PC. Model runners are labelled separately: residency changes/reloads can legitimately move RAM by
the model weight size. A standalone dispatcher harness is also distinct from the actual app.
The planner is already pinned in `models_ladder.yaml` and `vram.keep_alive_for()` returns -1;
GPU pressure may still require a ladder change. No RAM trimming or global process termination was
added, and no model/provider/pinning policy was changed based on the system-wide metric.

## Verification and remaining evidence

Regression coverage includes LRU/expiry/rehydration, active leases and error paths, weak-reference
release during session churn, approval bounds and replay, socket cancellation task cleanup,
unique output paths, streaming/profile bookkeeping, real owned subprocess/grandchild cleanup,
and gate PASS/FAIL/UNMEASURED including reused PIDs and unrelated system growth.

Exact commands, test XML/source fingerprints, local measured churn, applied diff and guarded
rollback are recorded in the task artifact directory `RAM-Fixes-2026-10-13` alongside `STATUS.md`.

Open evidence gates: causal reproduction on a historical revision; representative real app/model/
voice and native GUI soak; desktop/frontend memory; and multi-hour use. A short synthetic run
cannot close those gates or promise a fixed total system-RAM footprint. The original findings and
all pre-existing metrics are preserved. To reverse the patch, use the task's `restore.py` (dry-run
default, `--apply` only if each file still matches this task's final hash).

Development validation also exposed an existing nominally offline memory test calling real Ollama
reconciliation and triggering a ladder change. Its model response is now injected deterministically,
and the unavailable-model fallback is exercised explicitly. With `ISHTI_OFFLINE_EVAL=1`, non-e2e
pytest sockets reject real remote/provider and configured Ollama connections while allowing owned
loopback fixtures. The final test runner enables this boundary. Development runs that contacted
Ollama are preserved and excluded from the final offline qualification.

The boundary exposed additional pre-existing live dependencies: the keep-alive scope/reuse
checks now use doubles and an owned HTTP/1.1 loopback server, dispatcher state-flow injects a
scripted decision into the real context/workflow path, and self-model rendering/refresh tests
use explicit hardware/model probe inputs. The two actual model/voice-service scenarios are
marked e2e and remain explicit live acceptance gates. Offline rendering tests no longer assume
the CI machine has this PC's GPU or installed models. Socket blocking uses normal connection
refusal semantics so HTTP clients retain their ordinary error handling.
